# Deployment plan (Render free, Docker)

Ordered steps from "works on my laptop" to "graders can use it". Each step says who does it, what it costs and how
to check it worked. Nothing here needs code changes.

**Already verified locally in Docker (2026-09-23):** the image builds (727 MB, most of it the bundled Claude Code
CLI); it runs as a non-root user; `/health` reaches Supabase through the Session pooler; logged-out visitors are
redirected to `/login`; a wrong password gets a friendly 401 from real Supabase Auth; static files and security
headers are served; idle memory is **122 MB** (Render free allows 512 MB); a DEV run under a hard 512 MB limit peaked at 456 MB without being killed (run a1f525ef); an ICP phase ran **inside the container**
(CLI + plugin skills + our MCP tools) for $0.029.

## 1. Create the Render service ($0)

1. Render → **New → Blueprint** → pick the repo. It reads `render.yaml`: free plan, Docker, health check `/health`,
   `autoDeploy: false` (a deploy restarts the app and would interrupt a run).
2. Fill the secret values (`sync: false` in `render.yaml`):
   - `ANTHROPIC_API_KEY`, `APIFY_TOKEN` (**team**), `FIRECRAWL_API_KEY`
   - `SUPABASE_DB_DSN`: the **`lead_agent_app`** Session-pooler DSN (port 5432). **Never** the admin/postgres DSN
   - `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
   - `APP_BASE_URL`: `https://<service>.onrender.com` (makes cookies `Secure` and builds invite links)
   - `ALERT_WEBHOOK_URL` (after step 4; optional)
   - `SESSION_SECRET` and `ALERT_WEBHOOK_SECRET` are generated by Render
3. `DEV_LIMITS=false` from the first deploy (full limits: 10 leads, 20 companies, $1.25 per run; D-27/D-33). The owner sets any other value in Render → Environment if they want smaller runs.
4. **Check:** the deploy log ends with `Uvicorn running`, and `https://<service>.onrender.com/health` returns
   `"database":"ok","runs_configured":true`.

## 2. Supabase Auth settings ($0)

1. Authentication → URL configuration: **leave the Site URL as it is** (it's shared by every tool in the project and
   is only a fallback, D-65). Add the Lead Agent's addresses to **Redirect URLs**: `https://<service>.onrender.com/**`
   (and `http://localhost:8001/**` for local Docker tests). `**` covers `/accept-invite` and `/reset-password`.
2. Authentication → Sign-ups: keep **invite-only** (no public sign-up).
3. *(Optional; Supabase only allows editing email templates once custom SMTP is set up.)* Without it, Supabase's
   default Invite and Reset emails are used: plainer, but they work, because they carry the same `{{ .ConfirmationURL }}`
   link, which returns people to this app's `/accept-invite` and `/reset-password`. With SMTP set up:
   Authentication → Emails → Templates: paste `docs/email-templates/invite.html` into **Invite user** (subject: copy the
   one-line subject template from the top of that file) and `docs/email-templates/reset_password.html` into **Reset Password** (subject
   "Reset your Koya password"). They're shared with the other tools, so the invite is filled in from the details each tool
   sends with it (app name, description, inviter, role); anything missing falls back to neutral Koya wording. Both were checked with Go's html/template (Supabase's engine).

## 7. Keep it alive for grading ($0)

- Render free sleeps after ~15 min idle; the first request then takes ~30–60 s (cold start). While a run is active the
  app pings itself so it doesn't sleep mid-run.
- Supabase free pauses after 7 days idle: add a daily cron (e.g. cron-job.org) to `GET /health` for the grading window.

## 8. Operating rules

- **Never deploy while a run is active** (the Runs page shows it). A restart marks the run failed on boot (E-19).
- **Rollback:** Render → Deploys → pick the previous deploy → *Rollback*. There are no destructive migrations; new
  columns are additive.
- **Migrations** run only from the laptop (`scripts/migrate.py`, admin DSN), before deploying code that needs them.
- **Secrets** live only in `.env` (gitignored) and Render. Rotate a key by changing it in Render and redeploying.
